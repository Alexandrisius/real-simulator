# Типовые поломки real-simulator и лечение

## TLS в корпоративной сети: `self-signed certificate in certificate chain`

DLP/прокси подменяет сертификаты. Два слоя решения:

1. `NODE_USE_SYSTEM_CA=1` (уже зашит в `START.bat` релиза) — Node доверяет
   корням из хранилища Windows.
2. Не помогло → **корпоративный режим**: страница «Провайдеры» → тумблер
   «Корпоративный режим», или API:
   `curl -X PATCH http://localhost:3999/api/network-settings -H "Content-Type: application/json" -d '{"insecureTls":true}'`.
   Действует на исходящие вызовы провайдеров сразу, без перезапуска.
   Выключать обратно в доверенной сети (`"insecureTls":false`).

## Пустой ответ модели / tool-вызовы не приходят

- Думающие модели (Qwen3 и т.п.): reasoning съедает бюджет ответа. Поставь
  персонажу `maxTokens` ≥ 1500–2048 (PATCH `/api/characters/:id`).
- 20–60 секунд на ход — норма для таких моделей; таймаут хода движка — 3 минуты.
- Смотри сырой ответ: `GET /api/scenes/:id/apilogs` (поле `error` и `response_json`).

## Сцена сама встала на паузу

Причины ищи в событиях сцены (`GET /api/scenes/:id/events`, тип `system`):
- исчерпан лимит вызовов API или токенов на сцену (меняется в `config` сцены,
  счётчики — `GET /api/scenes/:id`);
- анти-повтор: 3 одинаковых вызова тула подряд;
- 5 неудачных ходов подряд (упавший провайдер, таймаут).
Возобновление: `POST /api/scenes/:id/control {"action":"resume"}` — но сначала
устрани причину (иначе пауза вернётся).

## Провайдер недоступен

- Проверка: `GET /api/providers/:id/models?test=1` — вернёт ok/error.
- LM Studio: модель загружена, Developer → Start Server, URL `http://localhost:1234/v1`.
- OpenRouter: ключ из openrouter.ai/keys; ошибка 401 — ключ, 429 — лимит.
- Порт 3999 занят другим экземпляром — закрой старое окно сервера или смени
  `PORT` (`start.bat` правит порт; dev: `npm run dev -- -p 4000`).

## Инструмент не появляется у агента

- Тул назначен персонажу? `toolIds` в PATCH `/api/characters/:id`.
- Виртуальные тула появляются по условиям: `shop_browse`/`shop_buy` — если в
  магазине есть товары или одежда с ценой; `reveal_attribute` — если в
  реестре есть hidden-атрибуты; `undress`/`wear` — если есть слоты одежды;
  `go_to`/`invite` — если в реестре есть места; `request_tool` — если
  включена опция сцены `allowToolRequests`; `respond_to_offer` — только у
  персонажа с висящими входящими предложениями; `leave_scene`/
  `block_character` — если включена опция сцены `allowAgentStops` (она
  включена по умолчанию) и участников больше одного.
- Движок перечитывает тула из БД каждый ход — перезапускать сцену не нужно.

## Действие не выполнилось (ok:false)

- **Граница**: отказ fail-closed, деньги целы, скоринг не считает. Текст
  отказа приходит только актёру (аудитория `none`) — ни владелец правила,
  ни остальные участников попытки и причины не видят; значения скрытых
  характеристик и чужих чувств в причине не раскрываются. Правило может
  действовать и на исходящие вызовы владельца (`scope: outgoing/both` —
  «сам с таким не сплю»). Границы в промптах не показываются — так задумано.
- **Анти-давление в предложениях**: тул с `requiresConsent` не исполняется
  сразу — создаётся предложение (TTL 6 ходов, потом сгорает). Дубликат
  висящего предложения и повтор после отказа отклоняются движком
  («меняй обстоятельства») — до конца сцены тот же тул той же паре
  предложить больше нельзя.
- **Не хватает денег** (`cost` тула > `state.money`) — отказ с остатком.
- **Физика одежды/места**: нельзя снять бельё поверх верхнего слоя, нельзя
  обнажить слот не в `undressPlaces`.
- **Enum-валидация**: «Параметр … не существует. Выбери из: …» — модель
  назвала несуществующего получателя/место/слот/товар/характеристику;
  допустимые значения перечислены в самой ошибке (у тулов БД список также
  виден модели в `enum` схемы).
- **Клампинг**: эффект не вышел за min/max атрибута — значение прижалось.
  Обратимость эффектов одежды тоже приблизительна из-за клампинга — это
  осознанный компромисс.

## «Сцена не может продолжиться» (уходы и блокировки)

Агенты могут сами закончить общение: `leave_scene` (флаг `left_scene`,
навсегда) и `block_character` (молчание пары в обе стороны). Когда живых
пар не остаётся, сцена завершается, а start/resume такой сцены отдаёт
ошибку с этим текстом. Лечение: сброс сцены (`POST /api/scenes/:id/reset`
— стирает блокировки, флаги ухода и предложения) или новая сцена/пересбор
состава.

## «Агент не видит» событие / знание

Это инвариант видимости, а не баг: агент видит только публичные события,
адресованные ему и свои. Личные сообщения других агентов, чужие скрытые
атрибуты (до verified/заявления), границы других — невидимы по дизайну.
Режиссёру адресовать лично: `inject` с `audience: [characterId]`.

## «Характеристики сами сбрасываются» / «одежда пропадает после сохранения»

Старые версии шлют из редактора персонажа ВЕСЬ state, каким он был при
открытии страницы — сохранение откатывало деньги, потраченные сценой, и
переодевание из карточки «Гардероб». В актуальной версии редактор шлёт
только изменённые ключи, а карточка гардероба синхронизирует форму после
надевания/снятия. Полный сброс («Заново», `POST /api/scenes/:id/reset
{"full":true}`) возвращает state к снимку на момент рассадки, но правки
редактора — и характеристики (PATCH), и конфигурацию одежды из карточки
«Гардероб» — накатываются оверлеем поверх снимка, они не сгорают. При этом
раздевание самими агентами внутри сцены «Заново» откатывает (это прогресс
сцены). Если значения всё же «чужие»: проверь, нет ли второй копии БД в
`.next/standalone/data` (запуск standalone-сервера создаёт её — удали папку
и запускай прод только через `start.bat`), и что редактировался тот персонаж
(id) и тот сервер (порт).

## `database is locked`

Живой сервер держит `data/app.db`. Не открывай тот же файл вторым писателем:
- свои скрипты — только с `SIM_DB_PATH=data/что-угодно.db`;
- e2e уже использует свой файл (`data/e2e-test.db`);
- сборка релиза (`make-release.mjs`) собирается на временной БД сама.
Чтение (SELECT) живой БД безопасно. При подключении ставится
`busy_timeout = 15000` — короткие конкуренции переживаются сами.

## Как проверить, что сломано: приложение или модель

- Провайдер `mock` + сцена: движок и UI работают без LLM — значит дело в модели.
- `npm run e2e` — весь цикл движка на mock-провайдере (свой файл БД).
- `npx tsc --noEmit` — типы перед любым коммитом правок кода.
- `start.bat status` / `log` — состояние и хвост лога продакшн-сервера.
- Живая проверка механик на реальной модели: `scripts/grok-live-check.mjs`
  (`--copy-providers --seed --run 10`; сервер на 3999 с отдельной БД
  `data/grok-test.db`).
